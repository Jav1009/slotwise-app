# SlotWise — Flutter Frontend

Mobile booking app for the SlotWise platform.  
Built with **Flutter**, **Provider**, **Dio**, and **Firebase Messaging**.  
Targets Android (and iOS with minor config). No Supabase dependency — auth is pure JWT.

---

## Prerequisites

- Flutter 3.x (stable channel)
- Android Studio or VS Code with Flutter extension
- A running instance of the SlotWise API (see backend README)
- A Firebase project (FCM push notifications)

---

## Setup

### 1. Install Flutter dependencies
```bash
flutter pub get
```

### 2. Configure API base URL
Edit `lib/core/constants/api_constants.dart`:
```dart
static const String baseUrl = 'http://YOUR_SERVER_IP:3000/api';
```
- Android emulator: use `10.0.2.2` instead of `localhost`
- Physical device on same network: use your machine's local IP (e.g. `192.168.1.5`)
- Production: use your deployed server URL

### 3. Firebase setup
1. Create a Firebase project at [console.firebase.google.com](https://console.firebase.google.com)
2. Add an Android app with your package name (`com.example.slot_wise_booking`)
3. Download `google-services.json` → place in `android/app/`
4. Run `flutterfire configure` to regenerate `lib/firebase_options.dart`

### 4. Run the app
```bash
flutter run
```

## Navigation Architecture

The app uses **named routes** via `AppRouter.onGenerateRoute` with `initialRoute: '/'` (SplashScreen).

After the splash animation + session restore both complete, `_maybeNavigate()` routes by role:

| Role | Route | Screen |
|------|-------|--------|
| admin | `/admin` | AdminDashboardScreen |
| staff | `/staff` | StaffDashboardScreen |
| customer/user | `/home` | CustomerShell |
| unauthenticated | `/login` | LoginScreen |

All role-routing uses `pushNamedAndRemoveUntil` (via `AppNav` extension) so the back button never returns to the login or splash screen.

**Logout** (all roles): calls `auth.logout()` then `context.goLogin()` — clears the stack.  
Customer logout is in `profile_screen.dart`. Staff/admin logout is in their dashboard AppBars.

## State Management

All state uses `Provider` (`ChangeNotifier`). Providers are registered globally in `main.dart` and are never recreated — they live for the app's lifetime.

Key patterns:
- **`_disposed` flag** on `BookingProvider` and `AdminProvider` — guards `notifyListeners()` calls in async finally/catch blocks against post-dispose crashes.
- **`_initialLoadDone` flag** on `AdminProvider` — `isLoading` getter only returns `true` until the first fetch completes, preventing permanent spinners for staff with zero bookings.
- **Polling timers** on `NotificationProvider` and `AdminProvider` — 30-second interval, started on screen init, stopped on dispose.

## Authentication Flow

1. **Cold start** → SplashScreen → `tryRestoreSession()` reads JWT from secure storage → calls `GET /auth/me` to validate → sets `_user` if valid
2. **Login** → `POST /auth/login` → save JWT to secure storage → register FCM token → `context.goAdminDashboard()` / `goStaffDashboard()` / `goCustomerHome()`
3. **Logout** → save token temporarily → delete from storage → `_user = null` → fire-and-forget `POST /auth/logout` with saved token → `context.goLogin()`

## Roles

| Role value | Access |
|------------|--------|
| `user` | Customer: browse services, book, cancel, reschedule, view own bookings |
| `staff` | Staff dashboard, manage own services/slots/bookings |
| `admin` | Full access — all services, all bookings, user management |

Role constants are in `UserModel` (`roleCustomer`, `roleStaff`, `roleAdmin`).
